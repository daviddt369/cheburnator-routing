# Cheburnator Routing

Единая сборка доменных и IP-списков для выборочной маршрутизации. Данные автоматически собираются из нескольких источников, проверяются и публикуются в форматах LST, sing-box JSON/SRS, Xray GeoSite/GeoIP DAT и Mihomo MRS.

**[Готовые ссылки на все наборы и форматы](LINKS.md)**

Списки определяют совпадения, а выход `direct`, `proxy` или `block` назначается в панели или конфигурации. Российский VPN-сервер с выходом `direct` выпускает соединение со своего российского IP.

## Наборы

| Имя | Содержимое |
|---|---|
| `ru-domains` | Российские домены Alpaca, дополнение itdog Russia outside, резервная копия из ru-not-ru-domain |
| `ru-ips` | Российские IPv4/IPv6 из Alpaca GeoIP RU и резервного источника |
| `proxy-domains` | Полное объединение itdog, Re-filter, Antifilter и Google AI; большой набор |
| `proxy-curated-domains` | Более компактное объединение itdog, Re-filter и Antifilter Community без полного реестра РКН |
| `proxy-ips` | IP/подсети Re-filter и адреса, найденные в смешанных доменных источниках |
| `service-*-domains` | Отдельные сервисы: YouTube, Discord, Telegram, Google AI, Google Play, Meta, TikTok, Twitter и другие |
| `service-*-ips` | Отдельные IPv4/IPv6-подсети сервисов, если источник их предоставляет |
| `category-*` | `anime`, `block`, `geoblock`, `news`, `porn`, `hodca` |
| `force-direct` | Собственные принудительные исключения для российского выхода |
| `force-proxy` | Собственные принудительные исключения для зарубежного выхода; публикуется, когда непустой |

`service-gaming-domains` импортирует существующий список владельца. В нём есть игровые платформы, Microsoft/Apple и обновления. Он не описывает все игровые серверы и их UDP-порты.

Категории заимствуются у источников, а не определяются автоматически по названию сайта. Ресурсы без известной категории сохраняются в агрегате. Сервисные наборы могут пересекаться с агрегатами: это нормально, но требует определённого порядка правил.

Для Happ и устройств с ограниченной памятью есть `geosite-compact.dat`: все категории и компактный агрегат, но без большого тега `PROXY-DOMAINS`. Подсети остаются в общем `geoip.dat`.

Например, `service-youtube-domains.lst` содержит доменные правила YouTube. `ru-ips-v4.lst` и `ru-ips-v6.lst` содержат чистые CIDR нужного семейства.

JSON и бинарные файлы содержат одинаковые поддерживаемые условия; тип точного домена не подменяется суффиксом. В DAT имена наборов используются как теги: `RU-DOMAINS`, `PROXY-CURATED-DOMAINS`, `SERVICE-YOUTUBE-DOMAINS`, `RU-IPS` и так далее.

## Панель

Выберите тип URL, семейство «Домены» либо «Подсети» и нужную политику выхода. Для доменов используйте LST либо sing-box JSON; для IP - `*-ips-v4.lst` / `*-ips-v6.lst` либо соответствующий JSON.

LST поддерживает обычные домены-суффиксы, `full:host.example` и `regexp:...`. Совместимость этих префиксов зависит от импортёра. `*-suffix.lst` содержит только чистые суффиксы, без точных и регулярных правил.

В показанной панели `.srs` обозначен как «заглушка», поэтому для неё используйте JSON/LST. Обновление файла на GitHub не означает автоматический Re-import: расписание панели настраивается отдельно.

## Рекомендуемый порядок на российской ноде

1. Служебные правила ноды.
2. `force-direct` и `force-proxy` (между ними сборщик запрещает конфликтующие домены).
3. Ваши сервисные исключения, например YouTube или игры через RU.
4. `proxy-curated-domains` **либо** полный `proxy-domains` через зарубежный выход.
5. `ru-domains` через российский `direct`.
6. Проверенные отдельные IP-исключения сервисов.
7. `ru-ips` через российский `direct`.
8. Общий `proxy-ips` через зарубежный выход.
9. Явно выбранный выход по умолчанию.

Общие доменные правила должны идти раньше общих GeoIP-правил. В `ru-domains` есть `.ru`, `.su` и другие зоны: заблокированный сайт в такой зоне должен попадать в доменное прокси-правило раньше. `conflicts.json.gz` в релизе показывает такие пересечения. Сборщик не вычитает из прокси-списка все российские доменные зоны.

IPv6-подсети itdog подключены для Cloudflare, CloudFront, DigitalOcean, Discord, Google Meet, Hetzner, Meta, OVH, Telegram и Twitter. Они дополняют соответствующие `service-*-ips` во всех форматах. Сервисные подсети не добавляются автоматически в `proxy-ips`: например, IPv6-источник Discord содержит общую сеть Cloudflare `2606:4700::/32`. Выход выбирается отдельным правилом сервиса. Агрегат `proxy-ips-v6.lst` может оставаться без маршрутов, если агрегирующие источники не предоставляют IPv6.

`proxy-ips` шире списка адресов конкретных сайтов: Re-filter добавляет сети целых ASN. Он не должен перекрывать явные доменные исключения. Полный реестр и GeoSite со всеми категориями могут быть слишком велики для конкретного роутера; для sing-box на роутере выбирайте отдельные SRS и компактный агрегат, контролируя фактическую память.

DNS на ноде настраивается отдельно: российские домены разрешаются с российским выходом, проксируемые - с зарубежным. Сервер может обработать только дошедший до него трафик. Имя приложения с телефона серверу не передаётся, а домен не всегда доступен при подключении по IP. Наборы не заменяют клиентские исключения приложений.

## Xray и Happ

Для Xray скачайте `geosite.dat` и `geoip.dat` в каталог assets. В конфигурации используйте `ext:geosite.dat:ru-domains`, `ext:geosite.dat:service-youtube-domains` и `ext:geoip.dat:ru-ips` с нужными `outboundTag`.

Happ позволяет указать собственные `Geositeurl` и `Geoipurl` в профиле маршрутизации и выбрать теги через `geosite:...` / `geoip:...`. Одного URL на LST для полноценного профиля Happ недостаточно: дополнительно нужны политика, порядок правил и DNS. Сам профиль привязывается к подписке. Порядок пересекающихся групп необходимо проверять на целевой версии клиента; этот проект не выдаёт непроверенный универсальный профиль Happ.

## OpenWrt и Mihomo

OpenWrt - ОС, формат зависит от установленного обработчика. Sing-box использует JSON/SRS; Mihomo - MRS; dnsmasq - отдельный конфиг nftset/ipset. В релизе есть `ИМЯ-dnsmasq-nftset.conf` и `ИМЯ-dnsmasq-ipset.conf`.

В конфиге dnsmasq имена sets - шаблонные `vpn_domains4` / `vpn_domains6`; sets, маршруты и правила firewall создаются отдельно. Такой экспорт содержит **только суффиксы**. Точные домены, regex и keywords туда не переносятся, чтобы не расширять их действие. О пропусках сообщает `dnsmasq_omitted` в отчёте. Для полной семантики используйте JSON/SRS/DAT.

MRS сохраняет точные домены, суффиксы и CIDR. Regex/keywords в бинарный domain-MRS не включаются; пропуски перечислены в `mrs_omitted`. Универсальной эквивалентности между всеми форматами нет.

## Автообновление и диагностика

Actions запускается ежедневно в 05:23 UTC (12:23 Красноярск), вручную и при изменениях кода/настроек. Отдельно выполняются тесты PR. Публикуется один полный релиз: сначала draft, затем загрузка всех файлов и проверка их SHA-256 через GitHub API, после чего назначается latest.

Проверенные снимки каждого источника сжимаются gzip и сохраняются в ветке `data`. Перед сборкой они восстанавливаются в локальный `source-cache/`. При сетевой ошибке, некорректном содержимом или сокращении числа правил более чем вдвое используется предыдущий снимок не старше 14 суток. Необязательный источник без копии отмечается как недоступный. Если отсутствует обязательный источник или минимальное число независимых поставщиков, публикация останавливается. Предыдущие рабочие файлы остаются доступны.

`manifest.json` в релизе содержит SHA-256 исходников, даты последней успешной загрузки и изменения содержимого, количество правил, ошибки, выбранные GeoSite-теги и ограничения экспортов. Успешная повторная загрузка не доказывает свежесть исходного проекта: поле `content_changed_at` не меняется при неизменном содержимом.

Смешанные источники сохраняют встретившиеся IP как IP-правила. Одноуровневые имена без точки в mixed-источниках отбрасываются с записью в карантин; намеренные правила целых зон, например `ua` у itdog, сохраняются в доменных источниках. Кавычки по краям домена удаляются только при явно включённом mixed-импорте. Для полного Antifilter допускается не более 100 некорректных строк и 0,1% входа; все пропуски отражены в отчёте. HTML, пустая загрузка и массовая порча данных не считаются рабочим списком.

## Хранение без накопления данных

- `main` содержит только код, настройки, исключения и документацию. Ежедневная сборка не создаёт в нём коммитов.
- `data` содержит один корневой коммит с текущим gzip-кэшем источников, `manifest.json` и `storage.json`. Каждая публикация заменяет этот коммит через force-with-lease. Родительские коммиты и теги кэша не создаются.
- Все пользовательские LST, JSON, SRS, MRS, DAT и конфиги dnsmasq находятся в Releases. Служебный список пересечений публикуется как `conflicts.json.gz`.
- Сохраняются три последних успешных релиза. Предыдущие автоматически удаляются вместе с тегами; незавершённые draft удаляются при ошибке публикации или после двух суток.
- Теги релизов указывают на код `main`, поэтому не удерживают прежние снимки `data`.

При первой миграции после успешной сборки `main` заменяется новым корневым коммитом без истории сгенерированных файлов. После успешной публикации прежние релизы старой схемы и их теги удаляются. Последующая история изменений кода сохраняется. Освобождение недостижимых объектов на сервере выполняет GitHub; его срок не задаётся workflow.

Политика хранится в `config/storage.json`: три релиза, до 45 MiB на файл сжатого Git-кэша и до 256 MiB на снимок кэша. При превышении бюджета или ошибке проверки новая публикация останавливается, предыдущий релиз остаётся доступен. Объём растёт только вместе с текущими исходными данными, без ежедневного накопления их версий. Gzip не применяется к файлам для прямого импорта в панели, чтобы сохранить совместимость.

## Локальная сборка

Требуется Python 3.12. Для LST/JSON/DAT внешние Python-пакеты не нужны.

```bash
python -m unittest discover -s tests -v
python scripts/build.py --output .cache/output
```

Полная сборка на Linux amd64 с проверенными компиляторами:

```bash
python scripts/install_tools.py
python scripts/build.py --output .cache/output --sing-box "$PWD/tools/sing-box" --mihomo "$PWD/tools/mihomo" --xray "$PWD/tools/xray"
```

Для локальной сборки с резервными снимками сначала загрузите кэш (нужен доступ к GitHub):

```bash
python scripts/storage.py restore
```

Затем сборка из восстановленных снимков выполняется без сети:

```bash
python scripts/build.py --offline --output .cache/offline --sing-box "$PWD/tools/sing-box" --mihomo "$PWD/tools/mihomo" --xray "$PWD/tools/xray"
```

Результат: `.cache/output/lists`, `.cache/output/rule-set`, `.cache/output/reports`, `.cache/output/dist`. SRS проходят компиляцию/декомпиляцию с проверкой условий, MRS - обратное чтение и проверку покрытия, DAT - обратное чтение и проверку всех тегов настоящим Xray при переданном `--xray`. Исходники `scripts/` и `config/` не изменяют серверы или старый репозиторий.

Для запуска публикации загрузите проект в новый публичный репозиторий с основной веткой `main` и включёнными Actions. Отдельный токен для ежедневной сборки не нужен: используется штатный токен workflow с `contents: write`. Изменение защищённой ветки может потребовать другой способ публикации.
